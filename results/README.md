# results/

Raw output committed as evidence. Each file is regenerated by a documented
command, so none of it is hand-written.

| File | Produced by |
|---|---|
| `dev.eval.json` | `py -3 -m textcodeguard.evaluate dev.jsonl --json results/dev.eval.json` |
| `unseen.eval.json` | `py -3 -m textcodeguard.evaluate unseen.jsonl --json results/unseen.eval.json` |
| `hard_eval.eval.json` | `py -3 -m textcodeguard.evaluate hard_eval.jsonl --json results/hard_eval.eval.json` |
| `merged_trainingpool.eval.json` | `py -3 -m textcodeguard.evaluate training/merged_dataset.jsonl --json results/merged_trainingpool.eval.json` |
| `benchmark.json` | `py -3 -m benchmark --json results/benchmark.json` |
| `model_stats.json` | out-of-fold model metrics (ROC-AUC, PR-AUC, Brier, log loss, per-fold, threshold sweep, feature counts). Ad-hoc analysis output, not part of the documented CLI. |
| `pooled_metrics.json` | per-configuration metrics pooled over dev + unseen + hard_eval. Ad-hoc analysis output, not part of the documented CLI. |

## What each evaluation file contains

- `records`, `risky`, `safe`, `ml_status`
- `configs`: one entry per configuration (`rules_only`, `rules_ast`, `ml_only`,
  `ml_only_conservative`, `combined`, `combined_corroborated`) with a full
  confusion matrix and per-class metrics
- `per_category_combined`: precision/recall/F1/support per canonical category
- `errors`: every false positive and false negative, with a **redacted** snippet
  preview, the firing rule IDs, ML score, language and provenance
- `warm_latency_ms`: warm latency after warm-up calls
- `environment`: Python version and platform

## Reading these honestly

`merged_trainingpool.eval.json` is the model's **training pool**. Its ML figures
are optimistic and are not a generalization result; it is included only to
quantify the deterministic recall gap. The three curated sets are small and were
used while authoring the rules, so they are development/tuned sets, not untouched
test data. See `docs/FINAL_REPORT.md` and `README.md` for the caveats.
